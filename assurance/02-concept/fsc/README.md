# FSC completeness check

This folder checks [WP-C-04](../WP-C-04-functional-safety-concept.md) for completeness with the fsc-builder method (WP-C-04 §14).

| File | What it is |
|---|---|
| [`fsc_model.py`](fsc_model.py) | Source of truth. It holds the item's block diagram (20 ASIL-relevant nodes, 5 external) and, for every (safety goal × node) basic event, the WP-C-04 FSRs that address it or why the node cannot violate the goal |
| [`fsc-coverage.md`](fsc-coverage.md) | Generated coverage table: 140 basic events |
| [`fsc_figures.py`](fsc_figures.py) | Figure generator. It draws WP-C-04 Figure 5-1 (safety goals → FSRs → allocated elements, with safe state, FTTI and the §9 trace) from WP-C-04 §3, §5 and §9. It fails if an FSR is missing from the §9 trace or names an element without a column |
| [`figures/`](figures/) | Generated SVG `fig-c04-5-1-sg-fsr-allocation.svg`, embedded in WP-C-04 §5. Do not edit by hand |
| [`test_fsc_figures.py`](test_fsc_figures.py) | Unit tests: the figure is current, every FSR is drawn once, and malformed tables are rejected |
| [`WP-C-04-fsc-completeness.xlsx`](WP-C-04-fsc-completeness.xlsx) | Workbook generated by fsc-builder. Tabs 04–08 are its fault trees, template FSRs, ASIL allocation and verification matrix; tab 09 maps them onto WP-C-04 |

The template FSRs in tab 05 are not LionDriver's requirements; the FSRs in WP-C-04 §5 are. The inherited ASILs in tab 06 are the generator's default. The allocation is WP-C-04 §4/§10: the SoC is QM and the envelope is the safety mechanism, with no decomposition.

## Regenerating

```bash
python3 fsc_model.py        # build/block_diagram.json, build/hara_consolidated_sgs.xlsx, fsc-coverage.md
python3 <fsc-builder>/scripts/generate_fsc.py build/hara_consolidated_sgs.xlsx build/block_diagram.json WP-C-04-fsc-completeness.xlsx
python3 fsc_model.py --postprocess WP-C-04-fsc-completeness.xlsx
python3 <fsc-builder>/scripts/recalc.py WP-C-04-fsc-completeness.xlsx
```

`build/hara_consolidated_sgs.xlsx` is a copy of the HARA workbook in which tab 13 holds the consolidated safety goals SG-01…SG-08 (from `trace/items/goals.yaml`) instead of the generator's per-function candidates.

Redraw Figure 5-1 after any change to WP-C-04 §3, §5 or §9:

```bash
python3 fsc_figures.py
```

`python3 fsc_figures.py --check` and `python3 test_fsc_figures.py` fail if the figure is stale; they are run in CI (`assurance.yaml`) next to the model check. CI runs `python3 fsc_model.py --check`. It fails if:

- a basic event has neither an FSR nor a reason;
- a cited FSR does not exist in WP-C-04;
- a WP-C-04 FSR is cited nowhere;
- the coverage table is stale.
