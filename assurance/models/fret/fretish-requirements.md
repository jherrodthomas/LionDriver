## Findings

| ID | TSR | Kind | Finding | Evidence | For | Status |
|---|---|---|---|---|---|---|
| FF-01 | TSR-103 | text differs from code | TSR-103 says a frame is rejected when its torque decreases in magnitude by more than Δ_down. The code never rejects a move toward zero: the lowest and highest allowed values are SAFETY_MIN(last, 0) - Δ_up and SAFETY_MAX(last, 0) + Δ_up, so 500 raw to 0 in one frame passes, and so does a sign change of up to Δ_up past zero. Δ_down (25) is instead the least descent the code demands once the command exceeds the measured EPS torque by Δ_meas (dist_to_meas_check), which is TSR-104's job. After a rejection the reference is reset to 0, not the last accepted frame. | opendbc_repo/opendbc/safety/lateral.h dist_to_meas_check and the reset block (opendbc 4d1a056) | WP-S-02 owner (reword TSR-103 to the coded rule, or change the code if the text is the intent) | fixed in WP-S-02 v0.53 (#391), text reworded to the code |
| FF-02 | TSR-103 | text differs from code | "Within any 250 ms window" reads as a sliding window. The code uses windows that restart once more than 250 ms have passed (MAX_RT_INTERVAL) and measures against the torque at the window start. Not binding at the baseline: 15 raw per frame at 100 Hz allows at most 375 raw in 250 ms, below Δ_rt = 450. | lateral.h rt_torque_rate_limit_check and the ts_torque_check_last update | WP-S-02 owner (state the window rule) | fixed in WP-S-02 v0.53 (#391) |
| FF-03 | TSR-307 | text differs from code | TSR-307(a) asks for revocation whenever the heartbeat reports "not engaged" while authority is granted. The code revokes only if the report persists: an "engaged" heartbeat before the 0.3 s mark ends the episode without a revocation. Either the requirement should say "continuously for 0.3 s" (a debounce) or a single not-engaged heartbeat is a gap. | panda/board/drivers/engaged_mismatch.h engaged_mismatch_tick (panda f4803c5) | WP-S-02 owner | fixed in WP-S-02 v0.53 (#391): "continuously for 0.3 s" |
| FF-04 | TSR-516 | requirement inconsistent with itself | TSR-516 demands the siren ≤ 0.5 s after detection, and for (b) on an EPS fault defines detection as the first fault frame. Its next sentence allows a persistence filter of up to 0.7 s. Read literally, the EPS-fault siren must sound ≤ 0.5 s after the first fault frame, and the reference build (≤ 0.96 s, WP-S-04 T-28) violates it. The intent (DQ-048: siren within the SG-02 1 s budget from onset) needs the EPS clause to replace the 0.5 s bound, not sit beside it. | WP-S-02 TSR-516 text; WP-S-04 T-28 | WP-S-02 owner (reword; no decision needed, DQ-048 already sets the intent) | fixed in WP-S-02 v0.53 (#391): the EPS clause replaces the bound |
| FF-05 | TSR-516 | not checkable as written | TSR-516 says when the siren shall start but not how long it sounds or how loud it is. Formally, a single 10 ms pulse satisfies "sound within 0.5 s". The code sounds 3 s for a heartbeat loss and holds the other triggers while their condition lasts. A minimum duration (or "until the driver acts") makes the requirement testable; loudness parallels BE-2.13 (no defined minimum volume). | panda/board/main.c siren_countdown, heartbeat_siren.h, eps_fault_siren.h | WP-S-02 owner | fixed in WP-S-02 v0.53 (#391): at least 3 s, audible over cabin noise (level set by WP-S-04 M-05; not formalised) |
| FF-06 | TSR-516 | boundary | (c) guards ordinary disengagements by requiring PCM cruise to be active "more than 0.5 s" after the first not-engaged heartbeat. The code fires at the 50th tick of the episode, which starts at 1, so 0.49 s after the first such heartbeat. The guard is 10 ms shorter than written. It errs toward warning. | engaged_mismatch.h ENGAGED_MISMATCH_SIREN_TICKS | WP-S-02 owner (minor) | fixed in WP-S-02 v0.53 (#391): "0.5 s (within one 10 ms task period)" |
| FF-07 | TSR-103 | text differs from code | Found in the first rewording of #391. Both checks are sign-aware in the code: they allow [min(r, 0) - Δ, max(r, 0) + Δ]. "Differs by more than Δ_rt" rejected +400 to -100, which the code accepts, and "a rise in magnitude by more than Δ_up" accepted +10 to -20, which crosses zero by more than Δ_up and the code rejects. | lateral.h dist_to_meas_check and rt_torque_rate_limit_check | WP-S-02 owner | fixed in WP-S-02 v0.53 (#391) before merge: the interval rule |

## Glossary

| Variable | Type | Meaning | In the code |
|---|---|---|---|
| `lka_frame_rx` | bool | a STEERING_LKA (0x2E4) frame from the SoC is in the TX hook this tick | opendbc safety/modes/toyota.h tx hook, 0x2E4 branch |
| `steer_torque_cmd` | int, raw | STEER_TORQUE_CMD of that frame | desired_torque, toyota.h |
| `tau_max` | int, raw | torque bound of TSR-102; baseline 1500 | TOYOTA_TORQUE_STEERING_LIMITS.max_torque |
| `lka_frame_rejected` | bool | the envelope does not forward the frame (tx = false) | toyota.h tx hook |
| `torque_reference` | int, raw | r of TSR-103's frame rate check: the previous frame's torque; 0 after a rejected frame or while authority is not granted | desired_torque_last, safety/lateral.h |
| `delta_up` | int, raw | TSR-103 Δ_up; baseline 15 per frame | max_rate_up |
| `delta_down` | int, raw | TSR-103 Δ_down: least fall per frame while the command exceeds the measured torque by more than Δ_meas; baseline 25 | max_rate_down |
| `torque_meas_max` | int, raw | largest measured EPS torque of the last 6 samples, scaled, widened by 1 (TSR-104) | torque_meas.max |
| `torque_meas_min` | int, raw | smallest measured EPS torque of the last 6 samples, scaled, widened by 1 (TSR-104) | torque_meas.min |
| `delta_meas` | int, raw | TSR-104 Δ_meas; baseline 350 | max_torque_error |
| `torque_rt_reference` | int, raw | r of TSR-103's window check: the torque at the start of the current real-time window, which restarts with the first frame more than 250 ms after its start | rt_torque_last, lateral.h |

| `lat_authority` | bool | lateral authority granted | controls_allowed |
| `eps_lka_fault` | bool | LKA_STATE of EPS_STATUS (0x262) is in the fault set | safety_eps_fault, toyota.h |

| `cause_reported` | bool | the revocation cause is reported to the SoC | pandaState fields |
| `car_safety_mode` | mode | the envelope runs a car safety mode (not SILENT, not NO_OUTPUT) | current_safety_mode |
| `heartbeat_rx` | bool | a SoC heartbeat (0xf3) arrives this tick | heartbeat_monitor.h |
| `authority_any` | bool | any actuation authority granted (lateral or longitudinal) | controls_allowed |
