## Findings

| ID | TSR | Kind | Finding | Evidence | For |
|---|---|---|---|---|---|
| FF-01 | TSR-103 | text differs from code | TSR-103 says a frame is rejected when its torque decreases in magnitude by more than Δ_down. The code never rejects a move toward zero: the lowest and highest allowed values are SAFETY_MIN(last, 0) - Δ_up and SAFETY_MAX(last, 0) + Δ_up, so 500 raw to 0 in one frame passes, and so does a sign change of up to Δ_up past zero. Δ_down (25) is instead the least descent the code demands once the command exceeds the measured EPS torque by Δ_meas (dist_to_meas_check), which is TSR-104's job. After a rejection the reference is reset to 0, not the last accepted frame. | opendbc_repo/opendbc/safety/lateral.h dist_to_meas_check and the reset block (opendbc 4d1a056) | WP-S-02 owner (reword TSR-103 to the coded rule, or change the code if the text is the intent) |
| FF-02 | TSR-103 | text differs from code | "Within any 250 ms window" reads as a sliding window. The code uses windows that restart once more than 250 ms have passed (MAX_RT_INTERVAL) and measures against the torque at the window start. Not binding at the baseline: 15 raw per frame at 100 Hz allows at most 375 raw in 250 ms, below Δ_rt = 450. | lateral.h rt_torque_rate_limit_check and the ts_torque_check_last update | WP-S-02 owner (state the window rule) |
| FF-03 | TSR-307 | text differs from code | TSR-307(a) asks for revocation whenever the heartbeat reports "not engaged" while authority is granted. The code revokes only if the report persists: an "engaged" heartbeat before the 0.3 s mark ends the episode without a revocation. Either the requirement should say "continuously for 0.3 s" (a debounce) or a single not-engaged heartbeat is a gap. | panda/board/drivers/engaged_mismatch.h engaged_mismatch_tick (panda f4803c5) | WP-S-02 owner |
| FF-04 | TSR-516 | requirement inconsistent with itself | TSR-516 demands the siren ≤ 0.5 s after detection, and for (b) on an EPS fault defines detection as the first fault frame. Its next sentence allows a persistence filter of up to 0.7 s. Read literally, the EPS-fault siren must sound ≤ 0.5 s after the first fault frame, and the reference build (≤ 0.96 s, WP-S-04 T-28) violates it. The intent (DQ-048: siren within the SG-02 1 s budget from onset) needs the EPS clause to replace the 0.5 s bound, not sit beside it. | WP-S-02 TSR-516 text; WP-S-04 T-28 | WP-S-02 owner (reword; no decision needed, DQ-048 already sets the intent) |
| FF-05 | TSR-516 | not checkable as written | TSR-516 says when the siren shall start but not how long it sounds or how loud it is. Formally, a single 10 ms pulse satisfies "sound within 0.5 s". The code sounds 3 s for a heartbeat loss and holds the other triggers while their condition lasts. A minimum duration (or "until the driver acts") makes the requirement testable; loudness parallels BE-2.13 (no defined minimum volume). | panda/board/main.c siren_countdown, heartbeat_siren.h, eps_fault_siren.h | WP-S-02 owner |
| FF-06 | TSR-516 | boundary | (c) guards ordinary disengagements by requiring PCM cruise to be active "more than 0.5 s" after the first not-engaged heartbeat. The code fires at the 50th tick of the episode, which starts at 1, so 0.49 s after the first such heartbeat. The guard is 10 ms shorter than written. It errs toward warning. | engaged_mismatch.h ENGAGED_MISMATCH_SIREN_TICKS | WP-S-02 owner (minor) |

## Glossary

| Variable | Type | Meaning | In the code |
|---|---|---|---|
| `lka_frame_rx` | bool | a STEERING_LKA (0x2E4) frame from the SoC is in the TX hook this tick | opendbc safety/modes/toyota.h tx hook, 0x2E4 branch |
| `steer_torque_cmd` | int, raw | STEER_TORQUE_CMD of that frame | desired_torque, toyota.h |
| `tau_max` | int, raw | torque bound of TSR-102; baseline 1500 | TOYOTA_TORQUE_STEERING_LIMITS.max_torque |
| `lka_frame_rejected` | bool | the envelope does not forward the frame (tx = false) | toyota.h tx hook |
| `torque_last_accepted` | int, raw | STEER_TORQUE_CMD of the last accepted 0x2E4 frame (TSR-103 wording) | desired_torque_last, safety/lateral.h; reset to 0 after a rejection |
| `delta_up` | int, raw | TSR-103 increase bound; baseline 15 per frame | max_rate_up |
| `delta_down` | int, raw | TSR-103 decrease bound; baseline 25 per frame | max_rate_down |
| `torque_rt_reference` | int, raw | torque at the start of the current 250 ms window | rt_torque_last, lateral.h |
| `delta_rt` | int, raw | TSR-103 window bound; baseline 450 per 250 ms | max_rt_delta |
| `lat_authority` | bool | lateral authority granted | controls_allowed |
| `eps_lka_fault` | bool | LKA_STATE of EPS_STATUS (0x262) is in the fault set | safety_eps_fault, toyota.h |
| `eps_status_timeout` | bool | 0x262 missing beyond its RX timeout (TSR-401) | RX check of 0x262 |
| `cause_reported` | bool | the revocation cause is reported to the SoC | pandaState fields |
| `car_safety_mode` | mode | the envelope runs a car safety mode (not SILENT, not NO_OUTPUT) | current_safety_mode |
| `heartbeat_rx` | bool | a SoC heartbeat (0xf3) arrives this tick | heartbeat_monitor.h |
| `authority_any` | bool | any actuation authority granted (lateral or longitudinal) | controls_allowed |
| `authority_granted` | bool | actuation authority granted | controls_allowed |
| `hb_engaged` | bool | the engaged flag of the last SoC heartbeat received | heartbeat_engaged, main.c |
| `hb_loss_detected` | bool | the TSR-407 heartbeat monitor detects the loss this tick | heartbeat_revoke, main.c |
| `siren_on` | bool | the panda siren output is driven | current_board->set_siren, main.c |
