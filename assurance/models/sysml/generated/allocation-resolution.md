# Allocation resolution

Generated by `assurance/models/sysml/tools/check_model.py --write` — do not edit by hand.

Every `allocated_to` value in [`assurance/trace/items`](../../../trace/items) is matched against the architecture model: element identifiers (`E-03a`, `host.selfdrived`, `panda.safety.toyota`, `IWDG1`), software units (`U-SAF-TOY`), the allocation short forms of WP-S-02 §2.1 (`P-SW`, `P-HW`, `SoC`, `HAR`, declared as aliases in the model) and the two non-element targets `EXT` and `OPS`. A value is **resolved** when every identifier in it names something in the model, **partly resolved** when some do, and **not resolved** when none do (free text such as "Firmware + IWDG").

This report is informational: it does not fail CI. It changes, and CI asks for it to be regenerated, whenever the model or an allocation changes, so a new unresolved allocation shows up in review.
