# Minimal cut sets

Generated by `fta_cutsets.py` from the fault trees in [WP-A-04](../WP-A-04-system-fta-fmea.md); do not edit. Each cut set is computed from the gate logic as written (OR = union, AND = product, absorption); transfers are expanded and repeated events are one variable. The tables of WP-A-04 are then checked against it. Findings here are input to the WP-A-04 review, not a verdict: an "effective" order argued from a latent or by-design condition shows as *effective*, one argued otherwise (e.g. common cause) as *argued*.

Order: *n* BE + *m* UE = basic events in the item plus undeveloped events (outside the item, driver or traffic). Effective: item basic events that are not latent or by design at the baseline (an event tagged `(latent, …)` or described as "by design" in WP-A-04 is taken as already present). Tags: L = latent or by design, S = SOTIF, C = carries a CCF tag.

Row results: *match* = a computed cut set; *effective* = omits only latent events; *argued* = a row marked effective that omits events the logic needs (the reason is in its comment); *outside tree* = names an event that is not in this tree; *reduced* = omits events the logic needs, with no stated reason; *not minimal* = a smaller computed cut set exists; *unrelated* = not a cut set; *in words* = not machine-checkable.
