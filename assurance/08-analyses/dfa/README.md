# Fault tree AND gates against the dependent failure analysis

Every AND gate in a fault tree says "the top event needs both of these to fail". That only protects the item if the
two inputs cannot fail together. This folder checks every AND gate of the
[WP-A-04](../WP-A-04-system-fta-fmea.md) fault trees against the independence claims of the dependent failure
analysis, [WP-A-03](../WP-A-03-dependent-failure-analysis.md) (§5.1). It uses a map of what each element depends on,
so the shared things where one cause could defeat both inputs are listed, and checks whether WP-A-03 has analysed
each one under the claim the gate relies on. Draft, AI-assisted (I0): the gate classification and the resource map
need review. The findings are review input for WP-A-03 (OI-12), not a verdict.

## How the check works

![Figure 2: three sources, the fault trees, the gate classification and the shared-resource map with the WP-A-03 claims, are joined for each AND gate across elements; the result sorts every gate into analysed under its claim, not analysed, dependence not known yet, no claim, or not an independence gate](fig-dfa-2-method.svg)

*Figure 2.* For each AND gate whose inputs lie in different elements, the script pairs up the inputs, finds the
resources both inputs of a pair depend on, and asks whether one of those resources' initiators (DFIs) is listed under
the gate's claim in WP-A-03 §5, or tagged with it in §4. "Analysed under the claim" is about coverage only: whether
the claim holds is the WP-A-03 verdict.

## Limits of the check

- **Claims are per gate, not per input pair.** A gate under two claims (G3.2, G5.3, G6.5) counts a resource as
  analysed if either claim lists one of its DFIs, even when the pair that shares it belongs to the other claim.
  Figure 3 credits the claim that lists the DFI.
- **A claim that covers only some inputs is not flagged.** G3.6 and G4.2 are under IC-01, but their third input, the
  PCM, has no claim (their notes say so). They are not counted with the gates that have no claim.
- **G3.4 is classed as an independence gate with no claim, but both its inputs lie in the PCM.** No pair of its
  inputs lies in different elements, so no shared resource is found for it. Classing it within one element, or as a
  common cause, would be more accurate.
- **The map is by element.** A resource reaches a gate input if the input's element depends on it. A part of an
  element that does not use the resource still counts. The unknown dependences (R-04 for E-01, R-07 for E-03) wait on
  the device schematic (WP-A-03 OI-2).

## Changing it

The analysis of record is WP-A-03. Edit [`and-gates.yaml`](and-gates.yaml) (each gate's elements and claim) or
[`shared-resources.yaml`](shared-resources.yaml) (what each element depends on, and the DFIs of each resource), then
run:

```sh
python3 dfa_gates.py      # dfa-gates.md and the resource map
python3 dfa_figures.py    # figures 1 to 5 of this page
```

CI runs both with `--check`, together with `test_dfa_gates.py` and `test_dfa_figures.py`. It fails when a fault tree
gains an AND gate that `and-gates.yaml` does not classify. Where each claim is drawn in figure 1 (`CLAIM_AT`) and the
gate in figure 5 (`EXAMPLE`) are set in `dfa_figures.py`.
